# 角色模式、执行拓扑与阶段设计

本文件在 Phase 2 读取。角色模式回答“谁负责什么”，执行拓扑回答“工作怎样推进”；不要用角色名称代替阶段设计。

## 六种角色模式

### 门禁评审型

成功结果是带证据的 findings 和准出结论。它读取已有产物与批准基线，按依赖排序 Gate，在最早阻断点停止，通常只写 review sidecar，不代替作者重写正文。

必须设计：审查对象、基线、证据优先级、严重度、Gate 顺序、最早停止、复审条件和稳定准出输出。

### 产物编写型

成功结果是稳定、可追溯、能被下游消费的正式 artifact。它区分已批准事实、可推导内容和必须由用户决定的高影响选择；自检不等于独立准出。

必须设计：上游事实源、内容边界、用户决策点、阶段产物、稳定路径、机器字段、追溯和验证。

### 访谈发现型

成功结果是经过用户确认的业务结论。它从已有材料和信息缺口出发，每轮只问会改变结论的少量问题，并保留冲突、决定和未决项。

必须设计：问题选择规则、每轮容量、确认点、未决项、停止条件、恢复摘要和正式产物转换边界。

### 工程执行型

成功结果是真实环境中可运行、可观察的变化。它先探查环境和已有能力，再限定修改范围、实现、运行和验证。

必须设计：工作区门禁、允许/禁止修改、依赖授权、隔离策略、失败路径、真实入口和可观察验收。

### 流程导航型

成功结果是基于机器事实源归一化的当前状态和少量下一步。它不代替 Writer 生产缺失产物，也不代替 Reviewer 批准。

必须设计：事实源、证据优先级、artifact 识别、状态归一化、置信度、最早阻塞点和 canonical 路由。

### 研究综合型

成功结果是在证据限制内可复用的综合判断。它严格区分事实、用户信息、官方声称、模拟、推断和未知。

必须设计：研究对象、样本和时间范围、来源边界、独立输入、综合规则、限制、反例和下游复用条件。

## 七种执行拓扑

### 线性阶段

事实源 → 规划 → 产出 → 自检。每阶段产生下一阶段所需的中间产物，失败回到最早未满足条件。

### 串行 Gate

Gate 1 → Gate 2 → Gate 3。前门失败立即停止，避免对已失效产物做昂贵后续检查；明确阻断与非阻断 finding 的处理差异。

### 访谈循环

识别缺口 → 提问 → 记录 → 用户确认 → 判断是否继续。每轮能暂停，并留下足够摘要供恢复。

### 增量写入

完成一段 → 局部门禁 → 写入稳定位置 → 下一段。返工只回到受影响段，最终仍做整体一致性检查。

### 工程闭环

环境探查 → 范围确认 → 实现 → 真实运行 → 观察失败路径 → 修复。语法检查不能替代真实运行。

### Controller/Subagent

Controller 准备输入和边界 → 隔离执行 → 独立审查 → 有限修复 → 汇总。Controller 负责完整性与权限，子任务不得扩大范围。

### 状态导航

读取机器事实源 → 识别 artifact → 归一化状态 → 找最早阻塞 → 给 1–3 个下一步。证据冲突只有会改变路由时才提问。

## 组合规则

- 一个 Skill 只有一个角色主模式和一个主要拓扑。
- 辅助模式承担独立、有限阶段。例如 Writer 末尾自检不自动成为 Reviewer。
- 嵌套拓扑写明开始与结束。例如 Research 可在一阶段使用 Controller/Subagent，之后回到增量写入。
- 多个角色贯穿全程且争夺最终决定权，通常说明职责应拆分。

## Phase 设计方法

复杂 Skill 的 Phase 是控制协议。每个必要 Phase 说明 Goal、Inputs、Actions、Intermediate Deliverable、Exit Criteria、Stop/Escalation 和 Resume。

进度清单只跟踪 Phase 状态和恢复位置，不复制正文。具有四个以上依赖阶段、多个 Gate、外部写入或可能跨轮暂停时，通常值得使用清单；简单单步 Skill 不需要为形式添加。
