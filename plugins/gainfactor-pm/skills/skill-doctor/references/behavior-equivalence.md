# 行为合同与双盲评估

本文件在 Phase 3 设计行为合同，在 Phase 5 做语义审计和双盲挑战。行为合同是当前任务的内部工作结果，不要求所有业务 Skill 新增永久配置文件。

## 行为合同

| 维度 | 要回答的问题 |
|---|---|
| 请求边界 | 哪些典型请求应触发？哪些请求不适用？ |
| 输入与证据 | 输入是什么？事实源和证据优先级如何？ |
| 权限与副作用 | 可读、可写和禁止修改范围是什么？ |
| 阶段依赖 | Phase 顺序为何如此？哪些可局部返工？ |
| 用户决定 | 哪些决定不可由执行者静默代替？ |
| Gate | 什么证据允许继续？最早停止在哪里？ |
| 中间产物 | 每阶段留下什么可检查、可恢复结果？ |
| 停止与恢复 | 缺信息、失败或暂停时怎样处理和恢复？ |
| 正式输出 | artifact、sidecar、路径和稳定字段是什么？ |
| 角色边界 | 与相邻角色怎样分工？ |
| 验证 | 哪些真实、可观察结果代表完成？ |
| 下游契约 | 谁消费输出？哪些标识或状态必须稳定？ |

对 update/refactor 先填写“改前行为”，再填写“候选行为”和证据。新增改进可保留，但不得掩盖原有关键行为退化。

## 语义审计

结构脚本只证明文件能被解析和路由。语义审计逐项挑战：

1. 执行者是否知道最先做什么，以及为什么不能跳过？
2. Gate 是可观察条件还是口号？失败是否真的停止后续工作？
3. 用户确认点是否绑定会改变结果的决策？
4. 每阶段是否留下可供暂停、复审和恢复的中间产物？
5. audit、Reviewer 或 Navigator 是否越权写入或代替生产？
6. 正式输出是否具有稳定位置和可消费字段？
7. 验证是否覆盖真实运行或真实结果，而非只验证措辞和语法？
8. 下游在不阅读对话历史时能否正确消费结果？

发现问题时引用具体 Phase、规则、文件或缺失行为，说明影响和修正建议。不能通过出现“证据”“Gate”“输出”等关键词判断已实现。

## 双盲协议

1. **封存目标**：记录目标路径，候选完成前不得读取目标内容，也不得把目标选为参考样本。
2. **准备简报**：只提供用户请求、输入、约束、允许副作用和完成期望。
3. **选择样本**：选择 2–3 个同类但非目标 Skill，只借鉴控制行为。
4. **独立重建**：完成行为合同、候选 Skill 和必要测试。
5. **揭盲对照**：打开目标，分别填写目标与候选行为合同。
6. **逐项判定**：比较 Phase、依赖、Gate、确认点、中间产物、权限、恢复、正式输出、验证和下游契约。
7. **有限修复**：只修复有目标证据或用户约束支持的差异；新增改进单独标记。

以下任一缺失即失败，不做平均分：核心 Phase 或依赖顺序、必要 Gate 或最早停止、用户确认点、中间产物、写入权限、暂停与恢复、正式输出、可观察验证、下游契约。

目标提前泄露时只能标记普通对照，不得宣称双盲通过。

## 六类初始挑战

### Reviewer 挑战

提供已有产物、批准基线和多个依赖检查。观察是否重建串行 Gate、严重度、最早阻断、证据位置、只读边界与准出结果。

### Writer 挑战

提供多个上游事实源、至少一个用户高影响选择和稳定下游。观察事实优先级、确认点、阶段产物、正式路径、自检和交接字段。

### Interviewer 挑战

只提供不完整意图和部分材料。观察是否复用事实、每轮只问少量高价值问题、记录冲突与未决项、支持暂停恢复并在确认后形成产物。

### Builder 挑战

提供真实仓库、已有组件、脏工作区和可观察验收。观察环境门禁、范围限制、隔离修改、真实运行和失败路径。

### Navigator 挑战

提供多种 artifact、冲突状态和可选分支。观察机器事实源、状态归一化、最早阻塞和少量 canonical 下一步。

### Research / Controller 挑战

使用两个变体：Research 变体检查事实、模拟、推断、未知与阶段门禁；Controller 变体检查隔离上下文、独立执行、独立审查、有限修复和汇总。两个变体分别判定，不能互相替代。

## 结果记录

每项记录 `present / missing / changed / improved`、证据位置和影响。总结果只允许 `pass`、`fail`、`not-blind` 或 `blocked`。
